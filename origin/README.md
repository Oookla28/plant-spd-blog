# 这个研究从哪里开始

当前的 SPD 几何审计研究，最早来自“叶境智鉴”农业视觉工程。原始项目面对的是一个很具体的问题：给一张田间叶片照片，系统能否识别病害、指出病斑位置，并在普通 CPU 上离线运行。

## 最初的工程目标

原始工程固定了 69 类植物病害，同时做图像级分类和像素级病斑定位。设计上把整叶语义与局部病斑细节交给两个模型。

- C0 使用 EfficientViT-B1，负责整叶上下文和稳定的语义判断。
- S2 使用 MSCAN-T，并加入 stride-4 细节路径，负责小病斑、弱纹理和局部空间关系。
- 两个模型合计约 8.72M 参数，导出后的 ONNX 模型约 33.6MB。
- 普通 CPU 上的双模型推理约为每张 0.25–0.35 秒。
- 内部 800 张验证图上的病斑定位 IoU 为 66.330%。
- 去重后的 PlantDoc 外部集包含 129 张图像和 14 个可映射病害族，等权分类融合 Top-1 为 49.612%。

系统可以输出病害候选、双模型独立判断、病斑热图、覆盖率和结构化记录，并在产学研实验中把识别结果交给机械臂内置 Agent，形成从图像采集到作业触发的闭环。

## 工程为什么逐渐变成研究问题

为了让系统真的能用，项目先做了大量数据和流程审计。原始资料中记录了 7,774 个 JPEG 文件、7,497 个唯一哈希和 265 个完全重复组，其中 123 个重复组跨越官方划分。标签层面同时保留了 34 种植物、115 个原始植物—疾病组合和 69 个疾病族。

这些数字带来一个直接的认识。一个结果变好，原因可能来自模型结构，也可能来自数据清单、标签映射、融合规则、读出方式、训练预算或评估口径。只看最后的分数，很难知道究竟是哪一层在起作用。

因此，研究路线开始收缩和重组。早期的双模型融合、CRCG、Shapley 权重、协方差估计器和 2×2 屏幕实验被保留下来作为历史对照，同时把当前主线改成更容易验收的几层问题。

1. 先固定输入和表示，问特征里是否存在可读信息。
2. 再固定特征，换成明确的 affine 或凸读出，检查读出族是否能到达。
3. 把 TRAIN 拟合、solver gap、正则化偏差和 HELD 泛化分开登记。
4. 最后才比较 Raw、Sqrt 和 Log 这样的 SPD 映射，并把每个结论的适用边界写出来。

## 从应用工程到 SPD 审计

在当前 Plant_SPD 主线中，图像经过卷积特征后构造 SPD 协方差矩阵，再比较 Raw、平方根和 Log 映射。这样做保留了最初工程对真实病害图像、69 类任务和可复核输出的约束，同时把一个模糊的“哪个几何更好”问题改成了可以逐层检查的问题。

E01 先观察到固定配方下 Log 的 HELD Macro-F1 平均高于 Raw 约 2.10 个百分点。随后 E02–E05 检查预算、裁剪、概率尺度、拟合和 Sqrt 参考，E06–E08 与 F2 把特征冻结后用认证读出检查“表示没有信息”这一解释，A 系列进一步显示训练配方可以把 TRAIN F1 从 24.178% 推到 89.193%。

所以今天的研究重点已经从“做出一个分数更高的模型”转向“解释一个分数差异需要满足哪些条件”。SPD 和 Log-Euclidean 几何仍然是研究对象，但它们被放进了更严格的表示、读出、优化和评估审计里。
